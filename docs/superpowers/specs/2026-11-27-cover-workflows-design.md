# lite-cdp：封面與操作故事設計

## 意圖

讓第一次打開 repo 的讀者先認識「顧客行為航圖」，再看懂一段可照做的真實操作。使用者已授權直接實作及 PR／merge／刪分支，這輪明確要求先設計探索；以下是實作者在先前授權內選定的方向。

## Approaches

比較品牌插畫（辨識強、操作弱）、介面拼貼（功能多、縮圖難讀）、主題封面加操作故事。選第三種，保留已完成的主題元件，以實際流程呈現價值。參考 [Telepy](https://github.com/NatLee/telepy) 的封面與功能圖庫分工、[巴哈自動化](https://github.com/NatLee/bahamut-automation) 的領域流程、[Stonk](https://github.com/NatLee/stock-trading-simulation) 的主題資料圖形；不複製其圖像。

## 本專案

| lite-cdp | 顧客行為航圖；藍色航線、事件節點與身分索引。保留／檢查現有 cover。 | 「選訪客與一次來訪 → 選事件看內容 → 開啟同一人的完整時間軸」。來訪按實際 session 分組，缺少識別不能連成虛構旅程。 |

檢查現有獨立封面和現行品牌／功能一致；品質合格即保留，不為這輪任務重做品牌。

操作故事：**選訪客與一次來訪 → 選事件讀取內容 → 開啟同一人的完整時間軸**。三張實際截圖以同一組示範資料／條件貫穿；每步一個動作與可觀察結果。已存在的獨立元件先接受這段流程驗證，只有實際缺口才修改／新增元件。

## 邊界

- Cover 指版本控制中的 README 封面，不宣稱已設定 GitHub Social Preview。
- 各圖從實際運行的隔離 demo 拍攝，來源要清楚，不能用假頁面模擬操作成功。
- 圖片不含憑證／私人資料；憑證僅透過環境變數提供。新增 demo 記錄須清理，既有 demo 狀態須還原。不發送外部通知。
- 延續既有架構／字型／依賴；不虛構資料欄位、指標或模型能力。
- README 主流程圖保持可讀；既有深色／手機／其他頁面圖庫保留但避免重複鋪滿。
- 桌面／手機、鍵盤與實際資料一致性需要核對。若操作顯示缺口，先重現，再做最小必要修改。

## 驗收

獨立 cover、三步操作圖與說明、可重現 capture 腳本、README 圖片連結完整；修正若改產品行為需對應測試與 build。審查完成後才交由主代理合併 PR、刪工作分支。
